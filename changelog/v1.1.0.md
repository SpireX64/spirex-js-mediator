# SpireX's Mediator - v1.1.0

## Breaking changes

- **`mediatorBuilder()`** no longer returns a separate builder object. It is now the **same function** as **`createMediator()`** (kept under a deprecated export). You get a **mediator instance immediately**; there is no `build()` step that produced the mediator from captured handlers.
- **Registration API moved onto the mediator**: **`registerHandler`** and the global event error callback live on the **mediator instance**, not on a builder returned by `mediatorBuilder()`.
- **`onEventError`** (on the old builder) was **renamed** to **`setEventHandler`** and is called on the mediator: `createMediator().setEventHandler(...)`.
- **`registerHandler`** and **`setEventHandler`** no longer return **`this`** for chaining (they return **`void`**).
- Registering a handler for a request type that **already has a handler** now **throws**; previously the new handler **silently overwrote** the old one in the internal map.

## Added

- **`createMediator()`** is **exported** as the primary factory (previously `createMediator` was internal-only).
- **Optional factory options** for **`defineRequest`** / **`defineEvent`**: **`name`** (used in error messages; defaults `requestUnnamed` / `eventUnnamed`) and **`stateful: true`** for events.
- **Forwarding**: an event listener may **`return`** another event or request object; the mediator **`publish`**es or **`send`**s it, including when a **`Promise`** resolves to such a value.
- **Promise rejections** from async listeners are delivered to **`setEventHandler`** (v1.0.0 only caught synchronous throws inside the microtask `try`/`catch`).
- **Stateful events**: last payload is stored; **`on()`** subscribers get a **synchronous** replay; **`once()`** skips replay (`ignoreState`).
- **`clearState(eventType)`**, **`getEventListenersCount(eventType)`**, **`disposeEventListeners(eventType)`**.
- **Stateful `publish` with no listeners** still updates stored payload so later **`on()`** subscribers can replay it.
- **`build()`** on the mediator instance returns **`this`** (deprecated, for callers that still chained `.build()`).

## Fixed

- **`send()`** when no handler is registered: error message includes the request type’s **`.name`** (from the factory), instead of a generic message without the type.

### Migration from v1.0.0

```ts
// Before
const mediator = mediatorBuilder()
    .registerHandler(handler)
    .onEventError(onError)
    .build();

// After
const mediator = createMediator();
mediator.registerHandler(handler);
mediator.setEventHandler(onError);
```

- Replace **`mediatorBuilder().…build()`** with **`createMediator()`** (optionally keep **`mediatorBuilder`** as a deprecated alias).
- Replace **`onEventError`** with **`setEventHandler`** on the **mediator**.
- If you depended on **overwriting** request handlers by registering twice, use a **single** handler or explicit unregister logic is not provided—register once only.
