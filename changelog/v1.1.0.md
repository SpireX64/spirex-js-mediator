# v1.1.0 — Runtime Simplification & Event Enhancements

This release evolves `@spirex/mediator` from a builder-based configuration model to a simpler, runtime-oriented API, while introducing new capabilities for event handling and reliability.

The focus of this version is:
- simplifying mediator creation and configuration;
- improving correctness and error handling;
- adding practical features for real-world event-driven scenarios.

## Improvements
### 1. Mediator Initialization
- Introduced `createMediator()` as the primary factory
- Removed the need for a separate builder and .build() step
- Configuration is now performed directly on the mediator instance

This simplifies the mental model and reduces unnecessary abstraction.

### 2. Handler Registration
- Handlers are now registered directly on the mediator.
- Registering multiple handlers for the same request now throws an error instead of silently overwriting.

This makes behavior explicit and prevents hidden bugs.

### 3. Error Handling
- Unified error handling for event listeners via `setEventHandler`
- Async errors (Promise rejections) are now properly captured

This ensures consistent behavior for both synchronous and asynchronous listeners.


## New Features
### 1. Event Forwarding
- Event listeners may return another event or request
- The mediator automatically dispatches the returned message

This reduces boilerplate and simplifies side-effect orchestration.

### 2. Replay last event
- Events can be defined with `replayLast: true`
- The mediator keeps the last event and replays it to new subscribers

Useful for handling late subscriptions without introducing shared state.

### 3. Event Utilities
- `clearReplay(eventType)` — clear last stored payload for `replayLast` event types
- `getEventListenersCount(eventType)` — inspect listeners count
- `disposeEventListeners(eventType)` — remove all listeners for an event

### 4. Improved Diagnostics
- Requests and events can have explicit `name`
- Error messages now include these names for better debugging


## Breaking Changes!
- Removed builder pattern `(mediatorBuilder().build())`
- Configuration methods moved to the mediator instance
- Renamed `onEventError` to `setEventHandler`
- Configuration methods no longer support chaining (return void)
- Duplicate request handlers now throw instead of overwrite

### Migration Notes
- Replace builder usage with `createMediator()`
- Move configuration calls to the mediator instance
- Ensure each request has only one handler

```ts
// Before (v1.0.0)
const mediator = mediatorBuilder()
    .registerHandler(handler)
    .onEventError(onError)
    .build();

// After (v1.1.0)
const mediator = createMediator();
mediator.registerHandler(handler);
mediator.setEventHandler(onError);
```

## Summary 
v1.1.0 makes the mediator:
- simpler to use (no builder, fewer abstractions);
- safer (explicit errors, better diagnostics);
- more capable (replaying events, forwarding, improved async handling).
